# 探索地图 / Exploration Atlas

一个 DeepSeek Harness Client 插件，用来回答三个问题：

1. 产品由什么构成？
2. Agent 如何使用这些构成？
3. 产品如何持续生长？

它不是插件清单，也不再给不同性质的维度计算平均分。地图把系统抽象与实验事实分开：

- 系统抽象说明能力如何形成闭环。
- 能力维度说明正在推进哪些边界。
- 证据记录说明什么已经发生、学到了什么、下一步验证什么。

## 默认闭环

捕获 → 记忆 → 协议 → 调用 → 行为 → 进化 → 下一次捕获

| 阶段 | 核心问题 | 代表探索 |
| --- | --- | --- |
| 捕获 | 如何把现场变成可处理的数据？ | 面聊、消息 |
| 记忆 | 如何让信息长期存在并可追溯？ | 笔记 |
| 协议 | 如何让新资源无需两两适配就加入？ | resource API |
| 调用 | 如何在正确场景提供正确上下文？ | 个人工作台、随手问、# |
| 行为 | 如何修改 Agent 搜索、验证和停止的规则？ | 轨迹、完成前验证 |
| 进化 | 如何把反馈安全地变成下一次变化？ | 自驱动迭代 |

点击阶段只显示三件事：目前成立的判断、相关探索、下一步实验。

## 七个能力维度

### 产品由什么构成

- 表现层可塑性
- 数据生命周期
- 协议组合

### Agent 如何使用这些构成

- 上下文组织
- Agent 行为规则

### 产品如何持续生长

- 协作边界
- 自进化治理

维度页只保留“问题、已学到、下一条边界”。详细事实统一放在证据页，避免重复。

## 四个页签

- 阶段：六个系统阶段及其因果关系，也是默认视图。
- 维度：三个根问题下的七个能力边界。
- 探索：每条探索的抽象、Takeaway、事实证据和下一实验。
- 灵感：记录新的想法或实验，选择其系统阶段和主要能力维度。

旧版补录数据会自动从五维 axis 映射到新结构，不会丢失。

## 资源 Provider

本插件注册 source 为 exploration 的端侧资源 Provider。其它插件可以通过统一资源接口搜索或读取探索记录：

    resource.search({ source: 'exploration', query: 'Loop' })
    resource.read({ refs: [{ source: 'exploration', id: 'all' }] })

返回内容包含系统阶段、能力维度、证据状态、抽象、Takeaway、证据和下一实验。
