# 消息（Messages）插件
<!-- The version and the package name below are filled in by scripts/build-package.sh when the package is built. -->

装在 DSH 侧边栏里的消息列表：左边是联系人，点开谁就是和谁的一对一对话。两个人不在同一个网络也能实时聊天。

## 核心设计：每个 ID 自带一个收件会话

插件不再需要「先建一个会话」这一步。每台 DSH 安装时自动生成一个**收件会话**（随机 topic），你的**添加码**就是这个收件会话 + 你的昵称：

- 把添加码发给对方，对方粘贴一次，就能给你发消息；
- **谁加谁都会立刻出现**：添加时会向对方的收件会话发一个 `ping`（只报"我加了你"，不算一条聊天消息），对方收到后自动建好联系人——所以你加了对方，对方那边立刻能看到你，反之亦然，不用等谁先发消息；
- 对方第一次发来消息时同样会自动建联系人（此时列表显示「对方发来消息，已自动添加」）。

所以添加联系人只有一个动作：**粘贴对方的添加码**。不需要新建、不需要房间号、不需要双方同时在线操作。

```
你的页面 ──HTTP/SSE──▶ 你的 DSH Host ──HTTPS──▶ 公共中继(ntfy.sh) ◀──HTTPS── 对方的 DSH Host ◀──HTTP/SSE── 对方的页面
```

两边 Host 各自订阅自己的收件会话，发消息时投递到对方的收件会话。页面只和本机 Host 的同源接口打交道，所以不用开端口、不用买服务器、不用注册账号。

## 让对方加入：两步

1. **装插件**：把 `chat-room-{{VERSION}}.tgz` 拖进 DSH 的输入框，然后说一句：
   > 安装我刚上传的联系人插件，解压后用 plugin_manager 安装这个目录
2. **加你**：打开 DSH 左侧「消息」→「添加联系人」→ 粘贴你发给他的添加码。

你这边只需要点「我的添加码」把自己的码发给对方。

## 用法

- 侧边栏「消息」图标 → 右上「+」= 添加联系人；底部齿轮 = 设置；首页/空列表也有「我的添加码」入口。
- 每个联系人独立：历史记录、未读红点、最后一条消息预览。
- 会话置顶：鼠标移到一条会话上，点右侧的小图钉即可置顶；置顶的会话排在列表最前并一直显示图钉，再点一次取消。「我聊」始终排在最前。
- 备注名：直接点左侧列表里的名字就能改（悬停出现小铅笔），也可以点开对话右上「信息」改名。
- 数据在 `$DSH_HOME/plugin-data/chat-room/state.json`：最多 30 个联系人，每人保留 200 条历史。

## 隐私与安全

- 添加码就是收件会话：**谁拿到你的添加码，谁就能给你发消息**。只发给想聊的人，不要公开发布。
- 中继服务方（默认 `ntfy.sh`）能看到明文内容，消息在中继上最长缓存 12 小时；插件本身不在服务器存任何东西。
- 收到陌生人的第一条消息会自动出现在联系人列表里——这既是零门槛的代价，也是它的机制；不想要就删掉该联系人。

## 公共中继的限制（ntfy.sh 免费版）

- 每天 250 条消息 / 每个出口 IP；突发 60 次后降为每 5 秒 1 次。超限发送失败，会显示原因。
- 单条消息正文上限 4096 字节（插件把整条信封限制在 3800 字节以内，约 1300 个汉字）。
- 消息缓存 12 小时，之后不能补拉。
- 想摆脱限制：自己在任意 VPS 上跑一个 ntfy（或兼容服务），在「设置 → 中继地址」和给对方的添加码里换成同一个地址即可，插件不用改。

## 端侧资源接口（Provider）

插件把自己的聊天记录注册成端侧资源接口（`@local/resource-api`）的一个 Provider，来源 id 是 `messages`，所以别的插件可以用同一套接口检索和读取本机的消息记录：

- 检索 `resource.search({ source: 'messages', query })`：按联系人名和消息正文做不区分大小写的匹配，一次最多读 12 个联系人的会话（搜索不会太重），结果按时间倒序，每条结果的 id 是 `联系人 id::消息 id`；
- 读取 `resource.read({ refs: [{ source: 'messages', id }] })`：`id` 可以是 `all`（所有对话）、`contact:<联系人 id>`（整段对话）或 `联系人 id::消息 id`（单独一条）；
- Provider 还带自己的标签（`labels`）和 `describe(locale)`（"3 位联系人" / "3 contacts"），消费者不需要知道什么是一个联系人。

记录存在 Host 端，Provider 走本机同源接口 `/plugin/chat-room/state` 和 `/plugin/chat-room/thread?id=` 读取，不碰浏览器的本地存储。接口约定见 `resource-api/README.md`。

## 结构

| 文件 | 作用 |
| --- | --- |
| `index.js` | Host 半边：收件会话订阅（每个中继一条）、按联系人的历史、本地 HTTP/SSE 接口 |
| `client.js` | Client 半边：消息列表 + 对话界面 + 添加码/设置弹窗 + 端侧资源 Provider（`messages`） |
| `protocol.js` | 纯函数协议：添加码、信封（含发件人收件会话）、SSE 解析 |
| `cordis.patch.yml` | 向 profile 插入 `chat-room` 插件行 |
| `test/` | 单元测试（`node --test test/*.test.mjs`） |

## 插件自己更新（1.4.0 起）

插件可以在运行时自己查更新并安装自己，**对方不用再收文件、也不用再装一次**：

1. **更新源**是一个 npm 包名（例如 `dsh-chat-room`）。它写在「我的设置 → 插件更新」里，也可以写进添加码：对方加你时自动学到更新地址。
2. 插件每 30 分钟查一次 registry；有新版本时面板顶部出现「发现新版本 x.y.z」，点「立即更新」就装。
3. 安装由 DSH 的插件管理器执行：先卸掉旧包再装新包，**HMR 开启时即时生效，不用重启 DSH**；聊天记录、联系人、添加码都存在插件数据目录里，更新后原样保留。

安全约束（更新源来自不可信的添加码，所以收得很紧）：

- 只接受 **npm 包名**，路径和网址一律拒绝；
- 只允许**替换成同一个包**：更新源指向别的包会被拒绝，不会把现有插件卸掉；
- 目标不是插件包（没有 bundle）时拒绝安装；
- registry 的版本不可变 + 带完整性校验，拿到的是官方发布的那个文件。

> 前提是这个包发布在一个对方能访问到的 registry 上。DSH 默认还会问 `registry.npmmirror.com` 镜像，国内可用。

**发布流程**（发布到一个公开仓库，插件从清单地址取新版）：

```sh
sh scripts/release.sh
```

它会打包、算 sha256、写 `release.json`、推到这个公开仓库。清单地址就是插件的更新源：

```
https://cdn.jsdelivr.net/gh/CeliaSy07/dsh-chat-room-releases@main/release.json
```

对方的插件每 30 分钟读一次这个清单；有新版本就提示，点一下即装，HMR 开启时即时生效、不用重启 DSH。

（如果更想用 npm registry，也可以：`npm login` 后 `sh scripts/publish.sh`，更新源填包名 `dsh-chat-room`。）

发布后：对方**只要装过一次 1.4.0**，他的插件就会自己发现新版本并在面板顶部提示，点一下即装，**不再需要传文件**。

## 测试开关

想先看看"有新版本"时的样子（红点、顶部横幅），不用真发布：往插件数据目录里放一个文件即可

```sh
echo '{"version":"1.5.0"}' > ~/.dsh/plugin-data/chat-room/fake-update.json
```

刷新面板，齿轮上就会亮红点；删掉这个文件就恢复。模拟版本不能真的安装（会提示"这是模拟的新版本"）。

## 升级与热更新

| 场景 | 做法 | 是否需要重启 DSH |
| --- | --- | --- |
| 我这边改源码 | 本地是工作区 link：改完把插件关掉再打开（或重启 DSH）即生效 | 否 |
| 对方升级到新版本 | 把我发的新 `.tgz`（**文件名要带新版本号**）拖进 DSH，说同一句安装口令 | 否，装完即时生效 |

要点：包管理器按**文件路径**记住包的来源，所以**同名文件重复安装会被判定为「已安装」而不会更新**；换一个新文件名（例如 `chat-room-{{VERSION}}.tgz`）再装，就会原地替换旧版本并热加载。

## 装配

- 安装：在 DSH 里让 agent 执行 `plugin_manager install_bundle`，目标填本目录绝对路径，或直接给 `.tgz` 包（`dist/` 下由 `scripts/build-package.sh` 生成）。
- 对方安装只需 1 次授权；插件零依赖、零安装脚本，不会触发 pnpm 构建脚本授权。
- 如果安装后插件显示未激活/没出现图标：在「设置 → 插件」里关掉再打开一次（重新加载 Host 模块），或重启 DSH。

## 自动同步到 GitHub

- `scripts/install-autosync.sh`：装 `post-commit` hook，之后每次本地提交自动 push 到 `origin/main`（网络失败静默跳过）。卸载：`rm .git/hooks/post-commit`。
- `scripts/sync.sh "说明"`：手动一键「提交 + 推送」。
