# Knowledge Context Reference

为 DeepSeek Harness 的全局输入框增加 `#` 上下文引用：

- `#笔记`：引用笔记模块中的全部笔记，包括普通笔记与自动维护的插件版本记录。
- `#面聊`：引用全部面聊逐字稿，并保留时间戳和话者姓名。
- `#消息`：引用「消息」（聊天室）插件里的对话——可以引用全部联系人的全部消息、某一个联系人的全部消息，或某一条具体消息。
- 也可以从菜单选择某一条笔记、某一段录音、某个对话或某一条消息。

选中后插入的是原子引用 chip。内容不会在选中时复制进草稿，而是在发送消息时读取最新内容：笔记、面聊与消息都通过端侧资源接口向拥有它们的插件读取（接口不可用时回退到本地 `localStorage` 与同源接口 `/plugin/chat-room/state`、`/plugin/chat-room/thread?id=…`）。因此引用始终使用发送时的最新文本。发送后，聊天记录仍显示同样的引用 chip；完整的序列化上下文只提供给模型，不会把 XML/Markdown 暴露在用户消息里。图片不会传给模型；消息引用保留联系人、发送者、收发方向与时间，系统内容不进入上下文；超长内容会在 48,000 字符处截断并明确标记。

消息引用的候选范围：`全部消息` 覆盖所有联系人；每个联系人还会单独列出「与 X 的对话」，可一次引用该对话的全部消息；单条消息候选在装有端侧资源接口时来自全部对话（最多读取 12 个联系人的会话），回退模式下只来自消息面板当前打开的对话（`state.activeId`）。聊天室只保留每个联系人的最近 200 条消息，更早的内容无法被引用。

## 架构边界

**本插件不拥有任何内容。** 笔记、面聊和消息由各自的插件持有，它们把内容注册成端侧资源接口的 Provider；本插件只按来源名（`notes` / `facechat` / `messages`）向统一接口要数据和最新文本：

- `#` 菜单用 `resource.search({ source, query, limit })` 生成候选；
- 引用序列化用 `resource.read({ refs: [{ source, id }] })` 取最新内容；
- 候选的文案、计数与分组由 Provider 自己提供（`labels`、`describe()`、`meta.group`），因此本插件不需要知道「笔记」「逐字稿」「消息」分别是什么。

接口不存在时（本插件单独安装、或拥有内容的插件未安装）自动回退到本地读取与同源接口，菜单与序列化行为不变。

具体接口见 [`../resource-api/README.md`](../resource-api/README.md)。

当前 DSH 的 input-trigger source 注册表允许任意触发符，但内置检测器只扫描 `/` 和 `@`。本插件因此注册一个正规的 `#` source，并通过可卸载的 adapter 包装共享 `InputTriggerController` 的 `track()`，补上 `#` 检测。为兼容链接插件与应用引用到不同打包实例的情况，adapter 还会同时覆盖实际运行中的 controller 和后续 `sessionOf()` 返回值。首页、现有会话和未来创建的会话因此第一次按下 `#` 都能生效。

聊天室数据不在浏览器里，而是由「消息」插件的 Host 半边保存在 `$DSH_HOME/plugin-data/chat-room/state.json`，并通过 `/plugin/chat-room/*` 暴露给页面。本插件只在打开 `#` 菜单和序列化引用时读取这些接口；消息插件不存在或接口不可用时，`#` 菜单会自动退回到笔记与面聊引用，不会报错。插件卸载时会恢复原方法和事件监听；不修改 `app.asar` 或现有 Notes / Facechat / Chat room 插件。
